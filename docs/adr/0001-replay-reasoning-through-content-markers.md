# 通过客户端内容标记回放推理载荷

Chat Completions 没有承载加密推理的字段，而 Codex Responses 上游在 `store: false` 时只能通过 `encrypted_content` 把推理项带到下一轮。我们在发给客户端的 assistant 内容里写入 `<!--cpa-replay:<引用>-->`，把推理载荷留在服务端，等客户端把这段历史原样回传时再还原。

## Considered Options

- **写进 `reasoning_content` 字段。** 不污染正文，但多数客户端不会把该字段写回下一轮历史，等于依赖客户端实现细节。
- **按历史前缀指纹旁路查表。** 不需要客户端配合，但客户端一旦调整历史顺序或并行分支，前缀就整段失配，而且无法区分同会话的两个分支。
- **只支持原生 Responses 客户端。** 不转换就不会丢，但编程客户端绝大多数走 Chat Completions，覆盖面接近于零。

## Consequences

- 标记出现在 `content` 里，用户可能看到。它必须是合法 HTML 注释，且不产生可见文案。
- 客户端若剥离 HTML 注释，功能静默失效：退化为不回放，不报错。命中率指标是发现这种情况的唯一途径。
- 引用无法解析时删除标记并记录事件，绝不把私有格式发给上游模型。
- 一个引用对应一整轮助手输出，不做块级拆分。单条记录损坏会丢掉整轮的推理，换取还原逻辑不需要处理块重排。
