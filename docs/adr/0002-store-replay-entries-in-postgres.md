# 推理载荷存 Postgres，未配置时降级到内存

回放条目保存的是 OpenAI 签发的加密推理载荷，需要跨请求、跨重启存活；一次 agent 会话常跨数十分钟，纯内存会丢掉大部分可回放的历史。CLIProxyAPI 宿主自身已使用 Postgres，但插件接口不暴露宿主的数据库连接，因此插件独立配置 DSN 并自带驱动。

## Considered Options

- **复用宿主的 Postgres 连接。** 最省配置，但 `pluginapi` 没有 storage 或 database 能力，需要改上游宿主，不是本项目能单方面决定的事。
- **插件自己写文件。** 不引入依赖，但要自己解决并发写、淘汰和损坏恢复，而这些正是数据库已经解决的问题。
- **只存可读的推理摘要。** 依赖零成本，但上游校验的是密文，摘要换不回合法的推理项，机制本身不成立。
- **只支持内存，不持久化。** 重启即失效，与这个功能要解决的场景直接冲突。

## Consequences

- 项目引入第一个非零运行时依赖（`pgx/v5`），构建链的依赖面扩大。
- 插件配置与宿主的 Postgres 配置各存一份 DSN，配置漂移会让回放静默失效。
- 未配置 DSN 时退回内存模式，功能可用但重启即丢。这个状态必须在管理界面上可见，不能只写日志。
- 载荷不做应用层加密：加密只是把信任转移给密钥持有者，不减少暴露面。该库的内容按凭据等级对待，README 需写明不可放进共享实例。
- 淘汰按 TTL 与总字节上限自动执行；被淘汰的引用按无效标记处理。
